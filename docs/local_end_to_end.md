# Local End-to-End Protocol

## 1. Create the environment

```bash
cd <prov-agent-loop-exps>
scripts/setup/create_venv.sh
.venv/bin/python scripts/setup/check_environment.py
```

MongoDB must be reachable at the host/port configured in `project.yaml`.
Redis must also be reachable at `localhost:6379` because Flowcept uses it for MQ/KV coordination in the online settings generated by this harness.

If your Flowcept settings define service binaries, use:

```bash
flowcept --start-redis
flowcept --start-mongo
flowcept --check-services
```

`flowcept --start-services` is not used here because that command is currently a placeholder. If MongoDB/Redis are managed outside Flowcept, start them with the local mechanism and then run `flowcept --check-services`.

For local Docker services:

```bash
docker run -d --name flowcept-mongo -p 27017:27017 mongo:7
docker run -d --name flowcept-redis -p 6379:6379 redis:7
```

If those containers already exist, start them instead of creating new ones.

Install the Flowcept DPL skill before any DPL session:

```bash
scripts/setup/install_flowcept_skill.sh
```

The script copies the canonical skill from the Flowcept checkout/package into `~/.codex/skills/agent-loop-provenance/SKILL.md`. Then start a new Codex session so the runtime sees the updated skill.

## 2. Baseline

Baseline is script-only execution. Codex may have helped create this harness, but it must not drive the run being measured.

```bash
.venv/bin/python scripts/run/run_local.py --condition baseline --repetition 1 --profile local_smoke
```

Then run:

```bash
.venv/bin/python scripts/analysis/run_query_suite.py --run-id <baseline_run_id>
.venv/bin/python scripts/analysis/build_metrics.py --run-id <baseline_run_id>
.venv/bin/python scripts/capture/export_run.py --run-id <baseline_run_id>
```

## 3. OPL

Run a fresh Codex session with `prompts/codex_opl.md`, then create a run pointing at the session JSONL:

```bash
codex "$(cat prompts/codex_opl.md)"
```

After the session finishes, find the newest JSONL:

```bash
find "${CODEX_HOME:-$HOME/.codex}/sessions" -type f -name 'rollout-*.jsonl' -print0 | xargs -0 ls -t | head -1
```

Then ingest and analyze:

```bash
.venv/bin/python scripts/run/create_manifest.py --condition opl --repetition 1 --profile local_smoke --codex-jsonl /path/to/codex/session.jsonl
.venv/bin/python scripts/capture/measure_ingestion.py --run-id <opl_run_id> --duration-sec 5
.venv/bin/python scripts/analysis/run_query_suite.py --run-id <opl_run_id>
.venv/bin/python scripts/analysis/build_metrics.py --run-id <opl_run_id>
.venv/bin/python scripts/capture/export_run.py --run-id <opl_run_id>
```

## 4. DPL

Run a fresh Codex session with the versioned provenance skill active and `prompts/codex_dpl.md`, then consume the JSONL:

```bash
codex "$(cat prompts/codex_dpl.md)"
```

After the session finishes, find the newest JSONL:

```bash
find "${CODEX_HOME:-$HOME/.codex}/sessions" -type f -name 'rollout-*.jsonl' -print0 | xargs -0 ls -t | head -1
```

Then ingest and analyze:

```bash
.venv/bin/python scripts/run/create_manifest.py --condition dpl --repetition 1 --profile local_smoke --codex-jsonl /path/to/codex/session.jsonl
.venv/bin/python scripts/capture/measure_ingestion.py --run-id <dpl_run_id> --duration-sec 5
.venv/bin/python scripts/analysis/run_query_suite.py --run-id <dpl_run_id>
.venv/bin/python scripts/analysis/build_metrics.py --run-id <dpl_run_id>
.venv/bin/python scripts/capture/export_run.py --run-id <dpl_run_id>
```

After multiple runs, aggregate local metrics:

```bash
.venv/bin/python scripts/analysis/build_metrics.py --all
```

## 5. Online capture option

Replay after the session ends is enough to validate the adapter mapping and query outputs. To measure ingestion while Codex is still running, start the session with a minimal first prompt:

```bash
codex "We are starting a PROV-Agent-Loop DPL experiment. Do not begin the workflow yet. Confirm that you will use the agent-loop-provenance skill when I send the experiment prompt."
```

Find the new JSONL, create the manifest, and start the adapter:

```bash
find "${CODEX_HOME:-$HOME/.codex}/sessions" -type f -name 'rollout-*.jsonl' -print0 | xargs -0 ls -t | head -1
.venv/bin/python scripts/run/create_manifest.py --condition dpl --repetition 1 --profile local_smoke --codex-jsonl /path/to/new/session.jsonl
.venv/bin/python scripts/capture/measure_ingestion.py --run-id <dpl_run_id> --duration-sec 600
```

Then return to the same Codex session and send the real prompt from `prompts/codex_dpl.md`.

## 6. Repetitions

For the paper, each repetition is a new run, not a replay of the same trace:

- OPL repetition 1/2/3: three different Codex sessions and three different JSONLs.
- DPL repetition 1/2/3: three different Codex sessions and three different JSONLs.
- Baseline repetition 1/2/3: three script-only workflow runs.

Reusing one JSONL three times is allowed only for adapter debugging.

## 7. Acceptance checks

For local smoke, missing Frontier-only evidence is acceptable and should appear as `missing_evidence`, not as script failure.

DPL should include execution plans, plan-step executions, loop iterations, evaluations, criteria/results, decisions, observations, beliefs, memory, and lessons learned when the session emits those annotations.

Local smoke is not expected to answer all paper queries completely. In particular, checkpoint/model-artifact, Slurm/node-hour, GPU telemetry, and full training-quality evidence may be missing until the Frontier validation run.
